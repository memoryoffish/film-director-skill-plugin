# 进度页：正在拍的片子，每一次生成都能看

一句话：拍片进行中开一页本地 HTML：每个单元一行，每一次生成一格（能直接放的视频、状态、用了几分钟、计费几秒），顶上写现在在干什么、开工多久、花了多少钱；页面自己刷新（有视频在放时不刷）。

## 读什么

- **生成记录**：调模型的脚本在每段视频旁边写的状态文件，`NAME.json` + `NAME.mp4`（`--jobs` 指它们所在的文件夹）。认的字段：`name`、`status`（`DOWNLOADED` 是出好了，`FAILED`、`CANCELED`、`UNKNOWN` 是失败，别的算还在生成）、`submitted_utc`、`timing.submit_time` / `end_time`、`usage.duration`（计费秒数）、`payload.model`、`payload.parameters.resolution`。重抽按名字认：`<单元>_t<n>`。没有 `task_id` 也没有 `status` 的 json 不算。
- **事件**（可以没有）：拍片的人一边拍一边追加的一行一个 JSON：`{"t": "15:02", "unit": "U2", "take": "U2_t1", "state": "pass|retake|check|note", "what": "第 1 次多了人声"}`。写了 `take` 的挂在那一格下面，只写 `unit` 的挂在单元上（判定落在这个单元最新的一次），最近四句放在顶上「现在」。
- **价格表**（可以没有）：`{"wan_price_cny_per_s": {模型: {"list": {"720P": 0.6}, "discount": {…}}}}`。给了才算花费：出好了的每一段，计费秒数 × 这个模型、这个分辨率的单价；不给只写时间。
- 另外可以给：故事（`--story`，放在顶上）、每个单元拍什么（`--units`，JSON）、单元的次序（`--order`）、剪出来的片子（`--cuts`，最新的三段放在上面）、估的总花费（`--estimate-cny`，画一根进度条）。
- 样子（`--style`，可以没有）：`fancy` 是深色放映厅，`warm` 是摊在桌上的拍片手账，`plain` 是本来的样子。只换样子和排法，页面上的事实一条不少；两套都把每一次生成排成一面墙（一格一次，同一单元的几次用线连着），顶上先说拍到哪了。见 [styles/](../styles/overview.md)。

## 步骤

1. 开拍前在 tmux 里起：`python3 scripts/progress.py <输出目录> --jobs <clips 目录> --events <运行目录>/progress.jsonl --prices <价格表> --title <片名> --every 60`。输出目录要先建好。
2. 生成记录在服务器上、页面在本机看时加 `--remote <主机>`：每轮重读 json，视频只拷新的和变了的。ssh 断了这一轮跳过，下一轮再来。
3. 拍片的人每做一个判断（这次过了、要重抽、在查什么）就往事件文件里追加一行，页面下一轮就有。
4. 不加 `--every` 只做一次。

## 规矩

- 只读，不碰生成记录；视频用相对路径链过去（`--remote` 时拷进输出目录的 `media/`）。
- 页面里的时间只有两处跟构建时刻有关：「更新 时:分:秒」「开工 N 分钟」（还在生成的那格写「已等 N 分钟」）。同样的输入，两次构建只差这几处。
