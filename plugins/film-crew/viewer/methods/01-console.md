# 展示台：一次拍片，每一镜进了什么、出了什么

一句话：上面放成片，底下一条镜头时间线；右边是当前这一镜所在的那一条视频生成（一条生成可以切成好几镜）：先是「喂进视频模型的」——发出去的每张图、首尾帧或参考视频、prompt 全文、参数；再往下每镜一行：白模静帧 → 这一镜用的关键帧（「这张图怎么来的」收起来）→ 成片这一镜。成片放到哪一镜，右边就换到哪一条生成。

同一页还有「节点图」视图，顶栏切换，共用时间线和成片，见 [02-graph](02-graph.md)。

## 什么时候用

- 内容是一次拍片：几十镜，每镜有输入（白模静帧、首帧、尾帧、参考图、prompt）和输出（成片里的那几秒）。
- 要回答「这一镜从哪一步开始走偏」：白模、关键帧、成片，哪一步和上一步不一样。
- 拍片 agent 交付时附一页；发出去的每部片，视频右上角默认有「展示台」按钮（盲看页上「揭晓」以后才出现）。

不合适：讲一个指标怎么算、只有一条时间线没有每段的输入。

## 步骤

1. **备清单**：运行目录用 `../formats/read_run.py` 读成清单（一部片一个）；skill 自己写了清单就直接用。先 `check_manifest.py` 查一遍。
2. **要节点图就先出工作流**：清单交给 `../comfyui/scripts/shots2comfy.py`（只要文件加 `--no-run`）。
3. **做页面**：`console.py <清单…> OUT_DIR [--workflows <工作流目录>]`，在读得到成片和图的机器上跑。几部片做在同一页，首页一部片一张卡。
4. **照用户的开法看**：首页点片卡 → 停在有问题的那一镜 → 点时间线、左右键、播放；1440×820 和 390 宽各看一次。下面「做完后检查」一条条过。
5. **发出去**：整个 OUT_DIR 一起发（发布时给 `data-src` 签名）；只改了模板时，把新模板套到已有的 `index.html` 上（换掉数据和媒体表两处之外的部分），不用重跑。

## 版面

1. **首页**：一部片一张卡。海报取有问题那一镜的中间帧，下面写片名、时长、镜数、有问题的时刻和一句话。点卡进那部片，停在有问题的那一镜。
2. **顶栏**：片名、类型、时长、镜数、模型，两个按钮切换「展示台 / 节点图」；右边每部片一个按钮，写有问题的时刻。镜头表是重建的，顶栏写从哪重建的。
3. **左栏**：成片在上，白模预演在下，一样大，预演跟着成片对时。
4. **右栏，这一条生成**：
   - 第一行：镜头名、起止、第几镜、拍什么；有问题的镜头加红框。第二行：「这条生成 U3_t2 用在 4 镜：」后面每镜一个按钮，点了成片跳过去。两行定高，写不下省略，悬停看全。
   - **「喂进视频模型的」一个框**（绿框）：
     - 发出去的每张图照发送的次序全摆出来：首帧、尾帧，然后图1、图2……每张写「图N 从哪来 · 是谁」，如「图3 参考图 · 女孩 全身」「图5 关键帧 · 4-1」「白模 · 1-2_a」。同一张发了两次照摆两次，写「和图5 同一张」。说明写在图下面，最多两行。
     - 参考视频写一行；参数把任务文件里发出去的都列上（model、duration、resolution、ratio、seed、audio、prompt_extend……）。
     - prompt 全文默认露四行，点「展开全文」看全；里面的「图N」「Image N」标出来，点了放大那张图。
   - **每一镜一行**（这条生成切成几镜就几行，当前这一镜亮起来）：

     | 镜头 | 白模静帧 · 只给出图模型看 | 这一镜用的关键帧 | 成片这一镜 |
     |---|---|---|---|
     | 4-1 0:45–0:48 | 白模 4-1（标「不进视频」） | 关键帧 k_4-1（标「进视频模型 · 图5」）；「这张图怎么来的」默认收起，点开是出图的输入图和出图 prompt | 成片里这一镜的中间一帧 |

     这一镜用的关键帧：当首帧的那张；一条生成切成几镜时，是参考图里属于这一镜的那张（清单的 `own_ref`）。这一镜没有自己的关键帧，写「沿用 4-1 的关键帧」。白模直接当首帧或参考图喂进视频模型的，加蓝框，标「白模直接进视频模型」。
5. **时间线**：粘在窗口底部。播放钮、时钟、上一镜 / 下一镜。一镜一根条，宽度按时长；只喂首帧、首尾都喂，两种深浅；有问题的镜头红框，有问题的时刻上面一个红三角。鼠标停在条上，弹出这一镜的小图和一句话。
6. **点图放大**：左右键先按发送的次序翻这条生成发出去的图，再翻每一镜的白模、关键帧、「这张图怎么来的」里的图和成片。

## 页面用到清单里的什么

| 页面上 | 清单里（格式见 `../formats/shots-manifest.md`） |
|---|---|
| 时间线、这一镜的文字 | 每镜的 `name`、`t0`、`t1`、`what`、`feed_note` |
| 「喂进视频模型的」 | `video.sent`：`first_frame`、`last_frame`、`reference_images`、`video` / `reference_video`，其余都是参数；`video.prompt` |
| 图N 后面的「从哪来 · 是谁」 | `pictures[图].label`；参考图是谁 `roles` |
| 「这张图怎么来的」 | `pictures[图].made_by` → `image_jobs` 的 `inputs`、`prompt` |
| 白模一栏 | 每镜的 `stills`（首、尾） |
| 单元里哪张参考图是这一镜的 | `own_ref` |
| 左栏两段视频、成片三帧 | `video`（成片）、`previz` |
| 顶栏、首页的卡 | `title`、`genre`、`model`、`recon`、`flag`；`plan` 为真时没有成片，时间线按镜头表、片长取 `seconds` |

## 伪代码

```
for 每份清单:
    for 每一镜 s:
        j = s.video.sent
        记下 j 发出去的：首帧、尾帧、参考图（全部，按次序）、参考视频、其余参数
        首帧、尾帧、参考图里有 made_by 的：从 image_jobs 记下出图的 inputs 和 prompt（同一个只记一次）
        白模 = s.stills（精简时，没喂尾帧就不放尾）
        成片三帧 = 抽帧(t0 + 0.12, 中间, t1 − 0.12)；另抽一张小图给时间线悬停
    图转成 JPEG，成片和预演转成网页码率
页面 = 模板 + 数据（内嵌 JSON）+ 每个媒体一个 <i data-k data-src>

打开(片):     换视频地址（不加载），画时间线，跳到有问题那一镜的开头
换镜(i):      还是同一条生成就只换亮起来的那一行；换了生成才重画「喂进视频模型的」和每镜那几行
跳到(t):      成片和预演的 currentTime = t；画播放头；换了镜就重画右栏
播放时每帧:   预演差 0.25 秒以上就对齐；换了镜就重画右栏
```

## 好用的规则

- **一屏放下**：1440×820 里顶栏、两栏、时间线都在，整页不滚。先量顶栏和时间线的实际高度，剩下的给中间；左栏宽 = min(0.32 × 页宽, (剩下的高 − 64) / 2 × 16/9, 560)，最少 300；右栏在剩下的高度里自己滚。
- **成片三帧**取 t0 + 0.12、中间、t1 − 0.12 秒，避开切点上的过渡帧。
- **图**转 JPEG，长边 1280，质量 82。
- **视频不预加载**：`preload="none"`。没加载时，成片的海报换成这一镜的中间帧，预演的海报换成这一镜的白模首帧；设 currentTime 只记下开始位置，不去下载。
- **预演跟着成片**：差 0.25 秒以上才对齐一次，对得太勤画面会卡。
- **时间线**：条宽不到 30 px 不写名字，靠悬停；刻度不超过 12 个、间隔至少 64 px，宽度变了重算。
- **布局不跳**：没有的东西画虚线框，写「这一镜没有白模」「这一镜没有关键帧」「还没开拍」；prompt 收起时一样高。
- **发到要签名的存储**：只支持一页，几部片做在同一页。媒体都写成标签上的 `data-src`，发布时只给这些地址签名，JS 拼的地址不签名。页面不读写 `location.hash`（外面的加载页可能占用 `#`）。
- **浅色、深色**：颜色都是变量，跟着系统；嵌进别的页面时，外面可以用 `html[data-theme]` 切。

## 片子多的时候：精简，嵌进片卡页

几十部片放一页（每部片一张卡，右上角「展示台」）时：

1. **精简**（`--compact`）：成片每镜只抽中间一帧，也当时间线的小图；白模尾帧只在这一镜喂了尾帧时才用；图的长边 960。展示台里成片「头」「尾」两格变成按钮，点了左边的成片跳到那一刻。
2. **视频只有一个**：片卡上已经有这部片的 `<video>`，展示台不再放第二个：`--no-encode`（不转码进输出；成片还要读得到，用来抽帧）。页面里调 `FilmConsole(数据, 媒体表, {video: F => 片卡上的 video, onBack, peers})`，打开时把片卡上那个 `<video>` 挪进左栏，关掉时放回原处。
3. **数据只放一份**：外面的页面把 `data.json` 内嵌一次（大了就 gzip 再 base64，打开时用浏览器自带的 DecompressionStream 解），第一次点「展示台」才解、才建。
4. **模板里能拆的三块**：整块 `<style>`、`<!--console-->…<!--/console-->` 之间的版面、`/*lib*/…/*/lib*/` 之间的脚本。嵌进去时给每条样式规则加上外层容器的前缀（`:root`、`body` 换成容器本身）；尺寸变量设在 `#console` 上。
5. **同步播放**：片卡左上角勾选框；「随机选」从筛出来的片子里随机勾 N 部（默认 4，2–6），「同步播放」开成一格一部，片卡上的 `<video>` 搬进格子。总时钟由页面自己走，每 0.5 秒对一次表，差 0.15 秒以上拉回来；一次只有一部出声。

```
片卡页:
    每部片一张卡：<video preload=none src=签名地址>，右上角「展示台」（盲看组揭晓后才显示）
    点「展示台」: 第一次 → 解内嵌数据，C = FilmConsole(数据, 媒体表, {video: 那张卡的 video})
                  盖一层全屏，C.open(这部片)
    点「← 回到片子」或 Esc: C.close()（video 回到卡上），收起那一层
```

## 没有现成运行目录的片子

片子的运行目录没有 `meta.json`，或者还没开拍：直接写一份清单（或先补一个运行目录再交给 `read_run.py`）。从剪辑表重建镜头表时一段就是剪进片子的一次生成；修片的片子用原片的镜头表，换掉改过的那一段；还没开拍的写 `plan: true` 和 `seconds`，白模静帧放进 `stills`。重建了什么、从哪重建的写进 `recon`，顶栏照写。

## 例子：一镜是哪一步走偏的

白模首帧里窗帘拉着，看不到窗外；喂进视频模型的首帧却画出了窗外的街道，成片照着首帧。点开「这张图怎么来的」：出图用的图2 是上一场的关键帧，那张里窗帘是拉开的，出图 prompt 让它「Keep from Image 2: the same room」。结论：走偏的是出关键帧这一步，视频模型照着首帧拍，没有走偏。只看成片，分不出是哪一步的错。

## 做完后检查

- 1440×820 和 390 两种宽度：没有脚本报错，整页不横向溢出；1440 时整页不超过视口高（最长的五分钟片也一样）。
- 单元任务：「喂进视频模型的」里图的张数、次序和任务文件的 `reference_images` 一样，重复的那张也在。
- 每部片每一条生成都过一遍（片子多时用脚本）：说明不出图框、图不互相叠；参考图没有标成「关键帧」；关键帧出图用了白模的镜头，白模那一栏不是空的；「没有文件」的数出来，分清是原文件删了还是路径没找对。
- 每部片打开就停在有问题的那一镜。点条、左右键、拖播放头，右栏跟着换；播放几秒，当前镜和预演都跟着走。
- 打开页面、换片、点镜头，都不请求视频文件；点播放才请求。
- 发布后用无头 Chrome 打开链接（`--dump-dom`，单独的 `--user-data-dir`）：每个媒体都是签名地址，图都加载出来，几部片都能放。
