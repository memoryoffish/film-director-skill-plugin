# 05 在真前端里核对：像人一样看一遍

一句话：用无头浏览器打开真 ComfyUI，先点开左边栏（人就是从那里点开一镜的），把工作流加载进去，查线接对没有、打开时看得全不全、线有没有从节点背后过、图和视频出来没有，再排队跑一遍回放，看这一镜该留的留下了没有、多留了别的没有；最后自己挑一镜截图看，把人接手的几条路走一遍。

## 推荐

- **照人的开法查**：人是从左边栏 Workflows 点开一镜的，侧栏开着，挡住画布左边 310 像素。只在「关了侧栏、按了适应窗口」的画面上截图，看不出人打开时左边一列会压在侧栏底下。所以检查脚本先点开 Workflows 再加载，不按适应窗口。
- **加载**：`app.loadGraphData(工作流)`；ComfyUI 用户目录里的工作流用 `/api/userdata/workflows%2F<路径>` 取。
- **查这几样**（脚本逐项给出，有一项不对退出码就是 1）：
  1. 前端不认识的节点类型（节点包没装上、类型名写错）。
  2. 线：文件里的条数 = 打开后的条数；按线号逐根对：起点节点、终点节点上的口名都和文件一样。前端里节点号是字符串，比的时候都转成字符串。别按「哪个口接着这个来源」去找：同一张图喂给同一个节点的两个口时（比如一张关键帧的图3 和图5 是同一张参考图），只会找到第一个口。
  3. 我们节点的参数按名字读回来，和文件对。参数整体错一位，多半是前端自己加了控件（seed 那一格）。
  4. **打开时看得全不全**：缩放不低于 0.6（再小前端不画字）；每个节点的屏幕位置都在看得见的那一块里（不被左边栏、顶栏挡住，不出窗口），不压在小地图下面。
  5. **线有没有从别的节点背后穿过去**：每根线按「出口 → 往右 15 → 各个拐点 → 入口左边 15 → 入口」的折线，每 3 像素取一个点，落在别的节点里就算。
  6. 节点上有没有还露着的空口。
  7. **图和视频出来没有**：图加载完、视频在放，而且放的是这一镜的 t0–t1。
  8. 回放：`app.graphToPrompt()` 转成 API 格式，`app.api.queuePrompt(0, p)` 排队，轮询 `/history/<id>`；要 success。跑完看这几样：
     - 该留的在不在：这一镜每张关键帧、这一镜的视频，按名字去 output 里取（`/view?filename=…&type=output`）；
     - 人看不看得到（资产系统开着时）：每个该留的文件在 Assets 面板里有没有卡片、是不是只有一张。查的是面板取的那份列表（`/api/assets`），新写的文件要等 ComfyUI 自己那遍扫描，最多等 15 秒；
     - 多留了没有：这一次报给前端的产出里，有没有不在单子上的（别的类型、别的名字）；资产系统开着时节点不报，所以全部跑完再看一次：面板里比开跑前新多出来的卡片，是不是都在单子上；
     - 节点变样没有：跑完以后哪个节点变了大小、多了控件（前端自带的预览又加上来了）。
- **这是这一头自己的验收，不是发片的一步**：把每镜跑一遍、留下资产，交清单的那条命令（shots2comfy）已经做了，不用开浏览器。检查脚本带 `--run` 是在真前端里再点一遍，看人点 Run 时会不会多出东西、节点会不会变样。改了节点包、排法，或 ComfyUI 换了版本以后跑。
- **人接手的几条路也走一遍**（检查脚本不管，自己在 8188 上做，或写几行脚本点）：
  - 拿：Assets 面板里右键一张卡片 → Insert as node in workflow，看插出来的值（`filmkit__片__S3.mp4 [output]`），后面接一个预览真跑一下；Generated、Imported 各试一张。
  - 找：右键 → Open as workflow in new tab，打开的是不是这一镜。
  - 改：在关键帧的提示词里打几个字，有没有「这是回放」的提示。
  - 存：存下来，重出一遍工作流，人改的那份还在不在、报没报出来。
  - 重启 ComfyUI，卡片还在不在。
- **自己挑一镜看**：脚本过了也要在 8188 上照人的开法打开一镜截图看：字看得清吗、看得出喂法和首帧是哪张吗、有没有别的镜头的东西、Assets 面板里是什么样。只核对连线，看不出人打开以后看不看得懂；不照人的开法看，看不出侧栏挡住了什么；只想着面板干净，会忘了人要拿什么接着干。
- **多个一起跑**：每打开一个工作流前端多一个标签页，隔 20 个刷新一次页面。刷新后别等 networkidle：前端会接着打开上次开着的那一镜，它的视频一直在取数据，网络闲不下来。全量跑放本机 tmux。

## 伪代码

```
打开前端（等 load，再等 window.app、LiteGraph），点开左边栏 Workflows
for 工作流:
    loadGraphData(工作流)
    missing = 图里类型不在 LiteGraph.registered_node_types 的
    for 文件里每根线: 前端里同号的线，起点对、终点口上接的是它、口名 == 文件里写的口名？
    读 FilmKit* 节点的 widgets（名字 → 值）
    等图加载完、视频放起来（最多 12 秒）
    看得见的那块 = 画布 − 左边栏 − 顶栏；cut = 有一部分在外面的节点；covered = 压在小地图下面的节点
    hidden_links = 折线上有点落在别的节点里的线
    empty_slots、no_media、off_shot
    --shots: 截图（就是打开时的样子）
    --run: 记下每个节点的大小；p = graphToPrompt(); id = queuePrompt(p); 等 /history/id；记 success / error、用时
           kept = 这一镜该留的文件（filmkit__片__关键帧名.png …、filmkit__片__镜头名.mp4）；kept_missing = output 里取不到的
           junk = 这一次报出来、但不在 kept 里的；resized = 大小或控件数变了的节点
           资产系统开着: 等到 kept 里每个文件都有卡片（最多 15 秒）；no_card = 没有卡片的；dup_card = 不止一张的
--run 而且资产系统开着: 开跑前记下面板里所有卡片；全部跑完等 12 秒（最后一遍扫描），新多出来、又不在各镜 kept 里的 = junk
退出码：全对 0，有一项不对 1
```

## 实测

- 第 3 项查得出参数整体错一位（seed 后面少了前端自己加的那一格）。
- 第 5 项查得出线从节点背后过：比如只喂视频的图比关键帧窄、靠左放，去视频的线就从关键帧右下角背后穿过去；靠右放就没有。
- 节点只写文件、不报给前端时，「多留了没有」只看报出来的产出就等于没查，所以加了看卡片的那两样。拿四份故意出错的工作流试过，都报了出来：
  - 视频留成一个新名字：等扫描、卡片出来，通过；
  - 把这张卡片的记录删掉再跑（文件在、卡片没有）：`no_card`；
  - 多接一个预览节点：`junk`（报出来的那份和新多出来的卡片两处都有）；
  - 跑的过程中往 output 里多放一个文件：最后的 `junk`。
