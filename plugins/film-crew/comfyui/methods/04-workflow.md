# 04 清单 → 工作流

一句话：清单里的每一镜（视频、它直接用的关键帧、关键帧用到的几张图）摆成「输入图的格子 → 关键帧 → 视频」，线不从节点背后过，简单的一镜按 100% 就能整个放下；写成 ComfyUI 的 UI 格式，放进它自己的工作流目录；跨镜头用的参考图放进 input，人改过的工作流不盖。

## 推荐

- **读什么**：只读清单（格式见 [00-interface.md](00-interface.md)）。拍片运行目录怎么读成清单，见 [../formats/read_run.py](../../formats/read_run.py)。`../viewer` 的节点图视图用的是同一条路：`../formats/read_run.py` 读运行目录，shots2comfy 出工作流。
- **只放必要的**：
  - 展开的只有这一镜的视频任务直接用的关键帧；它们的输入里，别的镜头的关键帧只当一张图，写它在那一镜里是什么（`s01 的首帧`），哪一镜都对不上的写「基准画面」，不往上追。
  - 一条生成切成几镜时，只展开名字对得上这一镜的那张关键帧；别的镜头的当参考图。
  - 同一张图只放一个节点；图到视频节点为止，不另放成片节点（放的是同一个画面）；说明卡片换成外面那个框的标题。
  - 不放：全片白模预演、没喂进去的白模静帧、站位描述、平面图、SaveVideo。
- **重抽不做成节点**：清单的 `takes` 里有几次，视频节点标题就写「· 生成 N 次，K 次报错」，明细进节点的 `properties.filmkit.takes`；关键帧的 `takes` 写成「· 画了 N 次」。
- **摆法**（目标：打开就看得全、字够大、每根线都能从头跟到尾）：
  - 三块，从左到右：输入图的格子 | 中间一列（这一镜的关键帧上下叠，首帧在上；只喂视频的图跟在下面，窄的靠右）| 视频节点。没有关键帧时图全进格子，格子挨着视频。都从顶上往下排。
  - 输入图排 1、2 或 3 列，挑打开时放得最大的那种（差不到 0.03 就少排几列）。一列摞 7 张要 1400 多高，只能缩到一半；排成两列是 4 行。
  - 线只在两列之间的空当里走；要越过一列时走一条横缝，两头各放一个拐点（ComfyUI 自带的 reroute）：
    - 格子里靠外的图：线从它这一行上面的缝里横着过去，过了最靠里的一列再散开去各个口（一张图几根线共用这一串拐点）；
    - 一张图既喂关键帧、又直接喂视频：去视频的那根从中间那一列的顶上或底下绕，哪边近走哪边；
    - 首帧派生出尾帧（同一列，要往回接）：从两张关键帧中间的缝里横着穿回左边。
  - 节点大小照前端实际排出来的算（口一行 20，第一个控件从 20×口数+6 开始，底下留 8；图、视频按自己的比例定高），前端打开后不再撑开。
  - 外面一个框，标题是这一镜（镜头名、起止、拍什么），字号按框宽挑。
  - 存进工作流的视图（`extra.ds`）按「1600×900、左边栏开着时看得见的那一块」（1208×798）算；装了节点包的前端打开时会按实际窗口再摆一次。
- **文件名带上拍什么**：`<镜头名> <拍什么>.json`（`S3 她把杯子放到桌上.json`）。Workflows 面板只列文件名，这样一列下来就是镜头表；放不下的名字，选中时面板自己滚动着显示。
- **放哪**：写进 `ComfyUI/user/default/workflows/filmkit/<片>/`，用户在 ComfyUI 左边栏 Workflows 里直接点开。清单（`--index`）放到这个目录外面，不然会被当成一个工作流列出来。
- **跨镜头用的图放进 input**：参考图、基准画面（哪一镜都不算自己产出的关键帧）拷到 `ComfyUI/input` 最上层，名字 `filmkit__<片>__<相对路径，/ 换成 __>`（`filmkit__zz_demo__refs__girl_front.png`）。人在 Assets 面板的 Imported 里看得到，能插成 LoadImage 接着用。不拷的两种：白模静帧只是那一镜的输入，在那一镜的图里从节点的口就能拿，两百多张放进去会把十来张参考图埋掉（面板一次只加载最近 100 件，搜索也只搜加载出来的）；某一镜自己的关键帧是那一镜的产出，跑过就在 output 里。节点自己还是直接读运行目录（那是 agent 的正本）。只能拷不能链。
- **人改过的工作流不盖**：每份工作流里记着自己的 sha1（`extra.filmkit.sha1`，算的是去掉这一项以后的文本）。重出时：文件和这笔对得上，是我们写的、没人动过，直接换；对不上，是人在 ComfyUI 里改过、存过的（前端存的时候会留着 `extra.filmkit`），挪成 `S3（人改过）她把杯子放到桌上.json` 再写新的，最后一行行报出来。没有这笔记号的文件（人自己另存进来的）一律不动。记号紧跟镜头名：面板里名字长了只显示开头，放末尾看不出哪份是人的。
- **每镜跑一遍，资产才在**：工作流写好以后，把每一镜排进队列跑一遍（`POST /prompt`，排队的格式自己拼，和前端转出来的一样；工作流原文跟着交，节点存文件时写进去）。回放只读文件，很快。倒着排（最后一镜先跑），Assets 面板里第一镜就在最上面。ComfyUI 没开就只放文件。
- **回执**：每镜的工作流文件、喂法、节点数、打开时的缩放、留在 output 里的文件名、跑成了没有。只发几镜时别的镜头的回执原样留着。
- **清理只动带记号的**：`--prune` 删这几部片对得上 sha1、又已经没有这一镜的旧工作流，和 input、output 里 `filmkit__<片>__*` 中用不到的文件。人自己的文件不带这个记号，碰不到。

## 伪代码

```
for 清单 in 交来的:
    登记表[film] = {run: root, film: 成片, keys: {关键帧名: 文件}}
    for 镜 in 清单.shots（给了 --shots 就只做那几镜）:
        g = 建图(镜)                        # 见 01-mapping 的伪代码
        for 列数 in 1, 2, 3:                # 输入图的格子排几列
            摆(g, 列数)：格子一行一行排，靠外的图在行上面留横缝、放两个拐点；
                         中间一列从上往下，往回接的线在两个节点之间留缝，越过它的线在顶上或底下留缝；
                         算框和视图：scale = min(1, 1208 / 框宽, 798 / 框高)
        留 scale 最大的那种
        写 UI 格式：nodes、links [号, 起点, 起点口, 终点, 终点口, 类型]、groups=[框]、
                    extra.reroutes / linkExtensions（拐点）、extra.ds、extra.filmkit、version 0.4
        旧文件：sha1 对得上 → 换掉；对不上 → 挪成「镜头名（人改过）拍什么.json」，报出来
        写的时候记一笔 extra.filmkit.sha1
    这部片的参考图、基准画面（不含白模静帧、不含某一镜自己的关键帧）→ 拷进 input/filmkit__片__相对路径
ComfyUI 开着: 新拷进 input 的图让资产库扫一遍；for 镜（倒着）: 排队跑一遍，等它跑完，记进回执
--prune: 删没人动过、又已经没有这一镜的旧工作流；删 input、output 里用不到的 filmkit__片__* 文件
```

## 实测

- 试过、放弃的排法：
  - 输入图只排一列 → 七张图的一镜缩到 0.5 以下，不画字；
  - 同一张图给不在同一列的两个节点各放一张 → 同一张图出现两次，节点多出一截；
  - 用曲线配拐点 → 横缝里的线会鼓出去 20 多像素压到标题。
- 写工作流很快，上百份约 2 秒。头一回要存关键帧、裁视频，每镜 2～5 秒；之后文件都在就不重写。
- 试过把喂进去的图全放进 input：白模静帧占了大半，Imported 一次只加载最近 100 件、搜索也只搜加载出来的，参考图搜不到。所以只放跨镜头用的。

## 局限

- 输入图多的镜头，格子和关键帧之间那条空当里线多（多的有十来根），都看得见，但要顺着找。
- 走线按直线排；用户把这些工作流的线改回曲线看，横缝里的线会略微鼓出去。
