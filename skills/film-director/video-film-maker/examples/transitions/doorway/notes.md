# 穿门洞：细节和试过不好的做法

从 [穿门洞](../../../transitions/doorway.md) 挪来的原文：伪代码、带数字的规则和检查、试过不好的做法。门槛的默认值在 [refs/practical/config-transitions.md](../../../refs/practical/config-transitions.md)「衔接检查」；每次实际用的值见各案例。

## 伪代码

```
c1 = generate("黄昏、不点灯，<人>走进<过道>，越走越暗，尽头是一扇关着的门，门缝漏一点光")
cut = darkest_frame(c1.tail)
c2 = extend(c1[cut-3s : cut], "走到门前推开门，光一点一点变亮……外面是<新地方>")
k = match(c1[cut], c2)                          # 对不上就让 c1 提前结束
if brightness(c2[k+1]) / brightness(c1[cut]) > JUMP:
    c2 开头乘回 c1[cut] 的亮度，保持到 c2 自己开始变亮，再用 1–1.5 秒放开
join([c1[..cut], c2[k+1..]])
```

## 带数字的规则和检查（原文）

- 「变暗」和「变亮」都要慢、都在镜头运动里发生；出口的光用约 **6 秒**从暗升到亮，不要一出门就是大太阳。

- 接缝亮度被续写提亮时**不用重抽，剪辑里补**：#2 开头乘 #1/#2 的亮度比，保持到 #2 自己开始变亮，再用 1–1.5 秒放回。

- #2 从暗到亮至少用 2 秒，没有一帧突然跳亮。

## 试过、不好的做法

- 冲进黑门洞，#2 从黑暗里出来直接到海边（没交代那头）：模型自己编出一条黑巷子、一道拱门连过去，地点显得怪。
- 「门洞转弯、看不到尽头」：天然山洞、石头过道上四次都生成成直的，出口一直看得见。
- 正午、门洞直通：黑不下来，门洞尽头一直亮着，一出门就是大太阳，明暗变化太明显。
