# 模型自带的切镜：只在接缝附近管

一句话：这一篇管两次生成调用（两个 clip）之间的接缝。模型在一次生成里自己切镜、叠化、跳变（提示词写了不要也会出现），是这段片子的内容，可以留着。只有两种情况要管：

1. **做转场时**：转场要落在两次调用的边界上，不能拿片段里自带的切换当成我们做的转场（比如过渡段中间被叠化掉，等于没有过渡）。
2. **接缝要用的那几秒里不能有**：遮挡转场的尾部窗口（约最后 2 秒）、续写要喂进去的最后约 3 秒、首帧接龙用的尾帧前后、上一个接缝之后的开头（剪辑时在接缝处做加速和叠化要用的约 1.2 秒）。切镜落在这里，接缝就坏了。

用[分镜单元](shot-unit.md)时，单元里的切点是我们写在表里的；表里没有、模型多切出来的那一刀才是毛病，按[生成后检查](checks.md)对表查，查法和下面一样。

两层画面半透明叠在一起（两个人叠着）这种难看的自带叠化，不算违反上面两条，看着不好就剪掉或重抽。

检测出的切点会差几帧，剪的时候怎么处理这几帧的误差，见 [剪辑和渲染](../4-edit/edit-render.md)「规则」。

**画面里的东西「变」**：局部、逐渐的变化本来就是内容：比如照片或画「活过来」时，画面从最下方开始一点点变成真的、往上蔓延，颜色慢慢从画的颜色变成真的，镜头往前推时相纸的白边或画框从画面四边被推出去，风车叶片刚开始转时局部有一点重影；又比如过渡段里满屏的云在原地变薄散开、露出下面的雪山。做 [媒介转变](../../transitions/optical.md) 时，整幅两层画面同时半透明叠在一起，就不是「变」过去而是叠化过去，效果差，要重抽。

## 怎么查

```
d[i] = histogram_distance(frame[i-3], frame[i+3])        # 颜色分布前后差多少
g[i] = mean_abs_diff(gray[i-1], gray[i])                 # 相邻帧画面差（颜色差不多的切换靠它）
candidates = local peaks of d where d >= FLAG
           + spikes of g much higher than both neighbours # 两路都挑候选
likely_cut = d >= CUT or g spike is large
zones = [start, start+1.2s] (接缝后开头) + [end-window, end] (尾部窗口 / 续写输入)
retake if any likely_cut in zones
overview = 整段每秒 4 帧的总览图，从头看到尾
```

- 数字只用来挑候选：快速运镜、遮挡物进出也会让颜色分布变很多；`CUT` 在自己的片子上标几处真切镜来定。
- **只看颜色分布，颜色差不多的切换查不出来**（木门 → 木墙、同一个人从正面切到背面、满屏同一种颜色的两层叠化）：加一路相邻帧画面差，总览图也要从头看到尾；做色彩匹配这种接法时，满屏同一种颜色的那几秒要逐帧看有没有重影。反过来，人转身、镜头推近，乍看像换了镜头，逐帧看是连续的，别误判。
- 运动的物体一顿一顿（每几帧停一下）也查不出来，要逐帧看物体。
- 反过来，火花、爆闪、屏幕亮起、车灯眩光会被当成切镜：候选都要看图确认。

## 发现了怎么办

- 在片段中间：留着，它是内容。
- 在接缝要用的那几秒里：剩下的部分还够做这个接法时，把剪点挪开，或者这一段在接缝那一侧只用切换之后的部分；不够就重抽，提示词里写「一个连续的镜头运动，任何时候都没有叠化、淡入淡出、切镜、两层画面」。
