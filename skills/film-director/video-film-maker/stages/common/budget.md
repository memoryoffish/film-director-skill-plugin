# 预算：时间和钱

一句话：每次开始生成之前，按计划估出要多久、要花多少，报给用户、等用户点头；拍的过程中拿实际情况和典型值比，慢了或贵了就报。

## 什么时候问用户

- **开工前**：镜头表定了、要开始生成之前，问一次总预算。用户同意了，或者给了上限，再动手。
- **中途**：花费或时间快用完预算时停下来，报一下已经花了多少、还剩什么没做，问要不要加。
- **出现异常时**：生成明显比典型值慢、网络偏慢，或者花费比估的高很多，先报，再接着做。

要用图像模型画参考图、关键帧时，开工前一起问：用不用、用哪个、画质（默认 high）、几张、多少钱（见 [refs/practical/gpt-image.md](../../refs/practical/gpt-image.md)）。

这些都是问用户的问题，每次的答复只管这一部片，不写进长期记忆。没人回答（非交互地跑）时怎么定，见 [规矩](rules.md)「没人回答时」。

## 怎么估

```bash
python3 scripts/budget.py estimate plan.json    # 按计划估时间和钱，最后一段就是问用户的话
python3 scripts/budget.py netcheck              # 现测网络，和典型值比
python3 scripts/budget.py actual clips/         # 已经生成的：计了多少秒、花了多少
```

- `estimate`、`actual` 不联网；`netcheck` 要连外网（访问 DashScope 的接口地址，给了 `--oss-url` 还要下载那个文件）。离线、或环境不让随便连外网时跳过 `netcheck`：时间和钱照样估得出来，少的是报给用户的「网络情况」，以及中途变慢时分不清是网络慢还是排队慢；报告里写明「网络没测」。

- **钱** ≈ 要生成的秒数 × 单价 × 重抽系数。
  - 续写要把喂进去的那几秒也算上。
  - 单价按分辨率和接口的排队档位定，快队列更贵。
  - 重抽系数先用典型值，再报一个「抽得多时」的上限。计划里不用写 `retake`，脚本默认取实测中位（约 1.2）；写成 2.0 会把预算估高近一倍。
- **时间** ≈ 每次调用的典型时间 × 调用数 × 重抽系数 ÷ 同时跑的个数。
  - 再加上 agent 自己写计划、看检查图的时间，以及剪辑、渲染的时间。
- 关键时刻的小样、关键镜头多拍的几条，在计划里单独列成调用，算进这次的估算（见 [生成后检查](../3-generation/checks.md)「挑好」）；看过成片后重拍最弱几镜的那一轮，到时候再报。
- 典型值和单价在 [refs/practical/budget-data.json](../../refs/practical/budget-data.json)（说明见 [budget-data.md](../../refs/practical/budget-data.md)）。

## 报给用户什么

- 预计时间：典型和慢的时候各多久。
- 预计花费：典型和最多各多少，单价按原价还是折扣价。
- 按什么假设：分辨率、调用次数、重抽几次、同时跑几个。
- 网络情况：`netcheck` 的结论（正常 / 偏慢 / 很慢）；跳过了就写「没测」。
- 问一句：可以开始吗，或者给个上限。

## 拍的过程中

- 每批生成完跑一次 `actual`，和估的比；进度页上一直有花费对预算的进度条（见 [可视化](visualize.md)）。
- 单次调用比典型值的正常范围慢很多：先跑 `netcheck`，再报给用户是网络慢、排队慢，还是这类镜头本来就慢。
- 重抽次数明显超过估的：多半是同一个毛病反复出现。先改写提示词（见 [生成后检查](../3-generation/checks.md)），别一直换种子烧钱，并告诉用户。

## 钱往哪花，边拍边调

依据是两条（见 [探索](explore.md)「冒险值不值」）：一部出彩的片比五部稳但不出彩的片都值；错多的片会被直接丢掉。在用户同意的总预算以内，怎么分自己调：

- **先保住不被丢掉**：片子里有明显的错（换了人、动作讲不通、镜头接不上），预算先花在改它们上。
- **稳了就往出彩上花**：明显的错改完以后，剩下的预算用来把片子做好：关键镜头多拍几种写法，试推荐以外的拍法。不为了省钱合格就收。
- **探索不成就停**：试的小样错多、连着几条都不成，停下这条路，退回推荐的做法，别把保底的钱也花掉。
- **预算紧、两头顾不全**：先保证没有明显的错，再把剩下的集中到一两个最要紧的镜头上，不平摊到每一镜。
- 觉得再多花一些很可能换来明显更好的片，照上面「中途」问用户要不要加。

## 局限

- 典型值来自几天、一个模型、一个地域，换了任何一个都要重测（[怎么重测](../../refs/practical/budget-data.md)）。
- 重抽系数：用这份 skill 的 11 部片实测中位约 1.2、范围 1.0–1.6；早期有一个单元重拍过 5 次。新模型、新类型先按偏高估。
- agent 自己花的时间和钱，是按 Opus 做一两分钟长的片子量的；片子更长、单元更多，会成比例变多。
